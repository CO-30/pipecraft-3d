# 図面解析の精度を測る

追加費用なし。すべて手元（PC）で動く。実物の図面は個人情報を含むので**リポジトリに入れない**（`bench-data/` は `.gitignore` 済み）。

## 1 件ぶんの用意（`bench-data/<案件>/`）
1. その工事の図面 PDF 一式を入れる
2. 正解を入れる（どちらか。両方あれば `truth.json` の値が優先）
   - **かんたん**: アプリの「新しい工事」→「図面から自動で3Dにする」で読み込み、壁・器具・ます・高さを**人が直して**、工事一覧の「書き出し」で出した `*.pipecraft.json`
   - `truth.json`（形は `truth.example.json`。図面の種類・縮尺、実際に使った数量はここに書く）
3. 人が確かめたら `confirmedBy`・`confirmedAt` を入れる（無いと結果に「⚠ 正解は未確認」と出る）

## 測る
```
npm run bench -- bench-data
```
結果は画面と `bench-data/results.md`。記録に残すときは数値だけを `docs/progress/log/` に書く。

## 比べ方（`src/bench/evaluate.ts`）
- 図面: 種類・縮尺の正誤
- 階: 階高・GL〜床の誤差(mm)
- 壁: 芯のずれ 100mm 以内・向き 5° 以内を同じ壁とし、長さで見た再現率（正解のうち読めた割合）・適合率（読んだうち正しい割合）、厚さの誤差
- 開口: 数の差
- 器具・配置図の物: 種類ごとに 2,000mm 以内で近い順に組にし、不足・余分・位置の誤差（中央値・最大）
- 数量: 読み取り結果に器具の候補を全部置き、画面と同じ決まりで「まとめてつなぐ」をした材料（`design.ts`）と、実際の数量の品目ごとの差（`quantity.ts`）。見出しは 管の長さの誤差（差の合計 ÷ 実際の合計）・部品の数の誤差（平均）・実際に無い品目の数
- 要確認: 読み取り画面に出した数

## 作り物の図面の基準
`src/bench/synthetic.bench.test.ts`。読み取りを直す PR はこの値を下げてはいけない（ふだんの `npm test` で落ちる）。

## 読み方の注意
- 器具は 2,000mm 以内なら「見つかった」に数える（隣の部屋でも数えることがある）。位置の確かさは「位置の誤差（中央・最大）」で見る
- 開口は数だけ比べる（位置は見ない）
- `.pipecraft.json` から作った正解は、アプリの読み取り結果を人が直したもの。直し忘れがあると読み取りに有利に出るので、図面と見比べてから `confirmedBy` を入れる
