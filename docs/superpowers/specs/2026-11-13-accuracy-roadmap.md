## 2. 今回の方針との整合 — 矛盾・確認が要る点と推奨

| # | 点 | 推奨（このまま進める） |
|---|---|---|
| A | 指示は「配管種別の識別・配管経路の抽出」だが、会社から届く図面（平面図・基礎伏図・立面図・配置図）は**建築図で、配管は描かれていない**。今のアプリは「建物と器具を読み → 配管はアプリが設計する」方式 | 精度は 2 つに分けて測る。① 建物・器具・寸法の**読み取り精度**、② 自動で設計した配管の**数量・長さが実際の施工とどれだけ合うか**（見積の内訳・竣工の数量と比べる）。配管が描かれた設備図からの読み取りは、マンション等で設備図が届くと分かった時点で後の段階に入れる |
| B | 正解データとの数値比較が必須だが、実物の図面は個人情報を含むので**リポジトリに入れない約束** | 図面は端末（または Claude のプロジェクト）に置き、**正解は数値だけ**（氏名・住所・図面の絵を含まない JSON）をリポジトリに入れる。比べる仕組みはリポジトリ、実物での実行は手元 |
| C | プロジェクトにある「与那原町1期給排水1.pdf」は**画像だけの PDF**（見積書・内訳書。文字の情報が無い）。今のアプリはスキャン PDF を読めない | 数量の正解（HIVP・VU の m 数、継手の数）として使える。ただし**同じ工事の図面が無い**ので、照合には図面とセットで必要。画像の文字を読む（OCR）は tesseract.js（Apache-2.0・無料・端末内で動く）が候補だが重いので、導入は報告してから（今は保留） |
| D | 「全国の小規模水道工事店へ販売」 | 今の自治体ルールは沖縄（那覇・沖縄市・南部）中心。Overpass は無料だが大量の商用利用は利用方針の確認が要る。販売の配布・課金・サポートの方法は未決（費用が出る可能性があるので、そこに入る前に報告する）。今は精度と使いやすさを優先 |

## 4. 解析精度の問題点（今わかっていること）
1. **精度を数字で測る仕組みが無い**。テストは作り物の図面（`testHouse.ts`）で、実物は手で確認しただけ（木造平屋 1 件・RC 4 階 1 件）。直して良くなったか・悪くなったかが数字で分からない
2. 器具は文字頼み。名前の無い器具（土間のシンク等）は出ない、位置は大まか（部屋の壁ぎわ）、個数の正しさは未測定
3. 壁: 通り芯が X1・Y1 形式でない図面、斜めの壁は未対応。階段のハッチを壁に読むことがある
4. 高さ: 展開図（給水・排水の高さ、器具の取付高さ）は読んでいない
5. 縮尺: 過去に「SCALE と 1/50 が別の文字」「詳細の S=1/20 を拾う」の誤読があった（直した）。他社の図面での正答率は未測定
6. 未確定の表示: 読めなかった理由の知らせはあるが、**項目ごとの確からしさ・「要確認」の一覧が無い**
7. スキャン PDF は読めない。200 ページを超える分は黙って読まない
8. 配置図（公共ます・メーター・道路側）の読み取り精度は未測定

## 5. 追加費用なしでできる改善
- 正解データの形と比べる仕組み（Vitest と Node の手元スクリプト。既存の pdfjs-dist を使う。新しいライブラリ不要）
- 正解を作る作業は、開発時に AI に下書きさせてよい → **必ず人が図面と見比べて確定**してから正解にする
- 規則（ルール）による読み取りの改善を、数字の悪い所から順に
- 確からしさの表示（もう持っている情報 = 通り芯の重なり、文字との距離、縮尺の決め方 から計算）
- 端末の学習（器具の向き）の対象を、位置・種類の直しにも広げる（保存は端末だけのまま）
- 数量の照合: 材料集計表（`materialSummary.ts`）と実際の見積内訳を品目ごとに比べる

### P0 の中身（最初にやる作業）
- 正解データ（`bench/truth/<案件ID>.json`、数値だけ）:
  - 案件の種類（戸建／アパート／マンション）・構造・階数
  - 図面ごと: 種類・縮尺
  - 階ごと: 階高、GL〜床
  - 壁: 芯線（両端の座標 mm）・厚さ・外壁/内壁、開口の位置と幅
  - 器具: 種類・位置（mm）・階
  - 配置図: 公共ます・メーター・道路側
  - 数量（分かれば）: 品目（管種・口径）ごとの m 数、継手・器具の個数
  - 確認者・確認日（人が見て確定したことの記録）
- 比べ方（`src/bench/`、純粋関数・単体テスト付き）:
  - 縮尺・図面の種類: 正誤
  - 壁: 長さで見た再現率・適合率（芯のずれ 100mm 以内を一致）、厚さの誤差
  - 階高・GL〜床: 誤差 mm
  - 器具: 種類ごとの個数の差、位置の誤差（中央値・最大、mm）、出なかった器具・余分な器具
  - 数量: 品目ごとの差（m・個）と率
  - 未確定として出した数（P1 以降）
- 実行:
  - リポジトリ: 作り物の図面（戸建・2 階建・RC 共同住宅）に正解を付け、Vitest で今の値を下回ったら落とす
  - 手元: `npm run bench -- <図面と正解のフォルダ>` で実物を読み、結果の表（Markdown）を出す。図面のフォルダは `.gitignore` に入れる
- ユーザーにお願いすること（P0 の後半・P2 で必要）: 実際の工事 2〜3 件ぶんの「図面一式＋実際に使った数量（見積の内訳か竣工の数量）」。戸建とアパート／マンションを 1 件以上ずつ
