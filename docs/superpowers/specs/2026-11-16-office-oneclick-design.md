# 事務作業のクリック数を減らす（申請図面のまとめ出力ほか）— 短い設計

## 意図
事務作業をする人の目線で、申請に出す図面・書類を作る操作を極限まで少なく・分かりやすくする。既存の機能は一切なくさない・壊さない。

## いまの手間（調査結果）
- 申請図面は 7 種類（排水縦断図・給水立面図・水理計算書・スリーブ表・ます表・材料表・見取図）。全部出すには「タブを切り替える → PDF」を 7 回、ファイルも 7 つに分かれる（14 クリック以上）。どの図面が作れる状態か・注意があるかは、タブを 1 つずつ開かないと分からない。
- 申請書タブの「提出書類のチェックリスト」は、付けたチェックが画面を閉じると消える（毎回付け直し）。

## 決めたこと（Claude の判断。ユーザー指示「聞かずに進める」による）
1. 申請図面の上に「📦 まとめてPDF」。押すと提出用の一覧が出て、図面ごとに「作れます / ⚠ 注意 n 件 / 作れません（理由）」が一目で分かる。作れるものは最初からチェック済み。「1 つの PDF にする」の 1 押しで全部が 1 ファイルに入る（2 クリック）。「見る」でその図面のタブへ移れる。
   - 中身は各タブの PDF と同じ（同じ作図処理を共通化して使う。下流端・起点・分岐・竣工図の設定も今のタブの選択どおり）。
   - 並び順: 見取図 → 排水縦断図 → ます表 → 給水立面図 → 水理計算書 → スリーブ表 → 材料表。
   - 個別の PDF / DXF / SVG / Excel のボタンは今のまま残す。
2. 提出書類のチェックリストのチェックを工事に保存する（`doc.site.application` の `checklist:<項目名>`。スキーマ変更なし。バックアップにも入る）。

## 方式の比較
- A. 作図処理を純粋関数に切り出し、タブ表示とまとめ出力の両方で使う（採用）: 出力がタブと必ず一致し、二重管理にならない。
- B. まとめ出力のために作図を別に書く: 早いがタブと食い違うおそれ（不採用）。
- C. タブを自動で切り替えて順に保存: 7 ファイルのまま、スマホで不安定（不採用）。

## やらないこと
- 申請書（Excel・様式 PDF）と道路の書類をまとめ PDF に混ぜない（形式が違う・既にそれぞれ 1 押しで作れる）。
