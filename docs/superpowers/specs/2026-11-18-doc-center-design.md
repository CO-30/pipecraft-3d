# 提出書類一式（書類センター）設計

指示: 「最終完成プロジェクト指示書」(2026-11-18) §7「最終的な書類出力画面」。質問せず自律で進める指定。

## ねらい
工事ごとに「出す書類」を 1 つの一覧にし、書類ごとの状態を見ながら 1 押しで保存する。今は申請図面（まとめてPDF）・申請書（申請書タブ）・道路の書類（道路の手続き）が 3 か所に分かれ、どれが出せる状態かは開かないと分からない。

## やること / やらないこと
- やる: 自治体の様式セットから必要書類を自動で並べる／状態（出力できます・確認が必要＋理由・作れません）／1 件ずつ出力／まとめて ZIP／直す場所へ移動
- やらない: 既存の出力ボタン・タブを消す・変える。保存データの形を変える。新しい依存を足す
- してはいけない: 未入力や注意があるのに「出力できます」と出す。未登録の自治体の様式を作れるように見せる。初期値のままの「取出しする」を確定として扱う

## 方式（検討した 3 つ）
1. **申請図面画面に一覧のダイアログを足し、作成処理を共通の関数に切り出す（採用）** — 既存の画面はそのまま、作り方は 1 か所。ZIP は無圧縮の自前実装（PDF・Excel は圧縮済みで依存ゼロ）
2. 申請書タブを一覧に作り替える — 既存 E2E・使い慣れた画面を壊す
3. ホーム画面に書類の画面を新設 — 図面の選択（下流端・起点）を持ち回す必要があり二重管理になる

## 構成
- `src/forms/produce.ts`: `produceForm`・`produceRoad`（`ShinseiForms.run`・`RoadPermitPanel.make` から逐語で移し、保存せず中身を返す）
- `src/export/zip.ts`: `zipStore`
- `src/ui/docCenter.ts`: 一覧と状態を決める純粋関数 `docRows`・`statusText`・`checkSummary`
- `src/ui/DocCenterDialog.tsx`: 画面。`ShinseiScreen` の「📂 提出書類一式」から開く

## 状態の決め方
- 申請書: 工事店名・設置場所・申込者（所有者）の氏名/住所が未入力、様式の注意（nanbuWarnings）、要確認の値（unverified）に入力あり、配管なし → 確認が必要
- 製品一覧表: 工事店名なし・載る製品 0 → 確認が必要
- 道路: 取出しが 1 つ以上で行を出す。使う人が「する/しない」を選んでいない・提出先未入力（私道は占用の宛名不要）・roadWarnings → 確認が必要
- 申請図面: まとめてPDF と同じ判定。作れない・注意ありが 1 つでもあれば確認が必要、1 つも作れなければ作れません
- 様式が未登録の自治体: 申請書の行は「作れません（未登録）」
