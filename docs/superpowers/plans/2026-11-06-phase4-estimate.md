# Phase 4 自動積算 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 配管ネットワークから長さ（実測長優先）・材料数量（余長・販売単位への切り上げ）・継手数量を自動集計し、単価登録・見積計算（材料費・施工費・諸経費・消費税）を行い、見積書・数量表を PDF / Excel で出力する。合格条件は「手計算で検証したテストケースと集計結果が一致する」。

**Architecture:** 積算は `src/model/estimate.ts` の純粋関数 `computeEstimate(doc)`（テスト可能な独立モジュール）。入力は Doc（建物・配管・器具＋新設の `estimate` 設定）だけで、結果はキャッシュせず毎回計算（二重管理なし）。継手の自動判定は `src/model/fittings.ts`（ノードの次数・角度・口径・系統から）。ユーザーの確定はノードの `fitting` に保存。出力は `src/export/{pdf,excel}.ts` を動的 import（初回表示のバンドルを増やさない）。

**Tech Stack:** 既存＋ pdf-lib 1.17.1 / @pdf-lib/fontkit 1.1.1（PDF・日本語フォント埋め込み）、exceljs 4.4.0（Excel）。フォントは Noto Sans JP（SIL OFL 1.1）を JIS X 0208 の文字＋記号にサブセット化した `public/fonts/NotoSansJP-JIS.ttf`（2.2MB、PWA で事前キャッシュしオフラインでも出力可）。

**Spec:** 設計書 第7章（7-3 計測方式・7-4 単位）、第8章、第10章、第13章 Phase 4、第14章（積算テスト）

## Global Constraints

- 内部単位は mm・円（整数）。表示は m / mm 切替。
- 実測長は図面・モデル値で上書きしない。見積数量には実測長を優先し、どの方式の値かを明記する。
- 余長は実測長・モデル長とは別の値（`extraRate`）として保持。
- 必要数量と発注数量を区別する。
- 積算設定・単価・確定した継手は現場データ（保存形式 v4）として Undo/Redo・保存の対象。
- 自動判定できない継手は「要確認」として一覧し、ユーザーが確定できる。

## 決定事項

| 項目 | 決定 |
|---|---|
| 計測方式 | `field`（現場実測 `measuredLength`）／`model`（3D経路長＝ノード間3D距離の合計）。`drawing`（図面から算出）は Phase 5 の図面読み込みで使う（型は既存）。区間ごとに使った方式を数量表・Excel 明細に表示 |
| 差の警告 | 実測長とモデル長の差が max(100mm, モデル長の10%) を超えたら警告。按分された実測長（`measuredApprox`）も警告 |
| 余長 | 現場の既定値（なし／5%／10%／任意、初期値 なし）。区間ごとに上書き可（`segment.extraRate`）。必要長 = Σ 使用長 ×（1＋余長率） |
| 集計単位（材料行） | 系統 × 材質 × 口径。電気・通信も同じ基盤（積算ルールは継手判定で別扱い） |
| 販売単位 | 単価表の行ごと。`perLength`（step mm 刻み、価格は円/m）・`straight`（定尺 L mm、円/本）・`roll`（巻 L mm、円/巻）。初期値: 配管＝定尺4m、電気・通信・冷媒＝1m 刻み |
| 発注数量 | perLength: ceil(必要長/step)×step を m 表示。straight/roll: ceil(必要長/L) 本・巻（端材は同じ行の中で使い回す前提） |
| 継手の判定（配管） | 次数2・一直線: 同口径同材質→なし（ただし定尺の継ぎ足しソケットは別計算）、口径違い→径違いソケット、材質・系統違い→要確認。次数2・折れ: 曲がり角 90±10°→90°エルボ、45±10°→45°エルボ、それ以外→エルボ（要確認）。次数3: 一直線の2本＋直角→チーズ、45°→Y管、それ以外→要確認。次数4→クロス（一直線2組でなければ要確認）。次数5以上→要確認。バルブ→バルブ。器具の接続口→器具接続継手。端点→なし。口径が混在→サイズを「20×13」と表記し名前に「径違い」 |
| 継手の判定（電気・通信） | 曲がり・直線・器具接続→なし。分岐（次数3以上）→ジョイントボックス |
| 定尺の継ぎ足し | 販売単位が straight の行は、一直線に続く区間（継手なしのノードで連続）ごとに ceil(使用長/L)−1 個のソケットを追加 |
| 継手の確定 | ノードに `fitting: { type, degree }`。次数が変わったら確定を無効にして要確認に戻す。「なし」も確定できる |
| 単価 | 材料行・部品行ごとに 材料単価・施工単価。単価キー = `pipe|系統|材質|口径`／`fit|種類|系統|材質|サイズ`。未登録は 0 円として「単価未登録」警告 |
| 施工数量 | 配管: 使用長（余長を含まない）を m 小数1桁に四捨五入。部品: 個数 |
| 金額の丸め | 行ごとに 数量×単価 を円未満四捨五入。諸経費: 率（(材料費+施工費+その他)×率 を四捨五入）または金額。消費税 = floor(小計×税率)（初期10%）。合計 = 小計＋税 |
| その他項目 | 試験費・運搬費などを手入力で追加（名称・数量・単位・単価） |
| 見積書 | 現場名・住所・作成日・宛名・工事名・発行者・備考・工事項目（材料／施工／その他）・数量・単位・単価・金額・諸経費・税額・合計 |
| 出力 | PDF（見積書・数量表・部品一覧・要確認）、Excel（見積書・数量表・部品一覧・区間明細の4シート） |
| 画面 | ヘッダーの「積算」で全画面の積算画面（タブ: 数量／部品／単価／見積）。PC は下部に総額・要確認件数の帯。区間パネルに実測長・余長、点パネルに部品の確定 |
| 表示単位 | m/mm 切替（端末ごとに保存）。数量表とヘッダーの総延長に適用 |

## Review Focus

1. 実測長がある区間はモデル長で上書きされず、数量に実測長が使われる → `estimate.test.ts: field length wins`
2. 余長・販売単位の切り上げで浮動小数点誤差により1本多く／少なくならない（例: 4000mm ちょうど → 1本）→ `exact multiple is not rounded up`
3. 継手確定後に分岐を追加すると確定が無効になり要確認に戻る → `stale override`
4. 金額の合計が行の合計と一致し、税は切り捨て → `tax floor`
5. v3 の現場データが v4 に自動変換され、`estimate` の初期値が入る → `repository.test.ts`
