# 2026-11-16 feat/nanbu-water-forms — 南部水道企業団（南風原町・八重瀬町）の給水申請一式

依頼: アップした実物の書類一式（南風原町の木造 2 階建て 1 件分。南部水道企業団の様式（記入済み）・受理された給水平面図/立面図・確認申請書・確認済証・建築図面）を徹底的に分析して開発に役立てる。細かいことは聞かず、監査して反映、マージと公開まで。

実物はすべて `bench-data/`（git に入れない）。テスト・証拠は作り物の名前・番地・番号だけ。

## 実物から分かったこと
1. 南風原町・八重瀬町の給水は南部水道企業団の様式。アプリは沖縄市の様式しか作れなかった
2. 企業団・沖縄市ともチェック表に「ガス給湯器に HT は NG」。アプリは「自動」の屋外の給湯を HTVP にしていた
3. 製品一覧表の実物は器具とヘッダー（PB管継手 ヘッダー7P など）にメーカーと認証の ○。アプリは管と継手を並べていた
4. 申請者・設置場所・確認番号・面積・階数・構造・道路の幅員・工事予定は確認申請書・確認済証の PDF に文字で入っている（全国共通の様式）
5. 企業団は水理計算を 0.2MPa で計算（穿孔時書類確認）
6. 平面図・基礎伏図・配置図は複合機のスキャン（画像だけ）で、自動 3D は読めない（今回は対象外。下に敷いてなぞる）

## 作ったもの
- 申請書タブ（南風原町・八重瀬町）: 「給水申請書類一式 (PDF)」＝ チェック表 → 穿孔時書類確認 → 給水申込書＋委任状＋見取図 → 臨時用給水に関する誓約書（臨時給水ありのとき）→ 様式第6号＋見取図 → 横断面図（道路の手続きの横断図）・オフセット → 竣工検査項目 → 給水の立面図 → 製品一覧表。罫線から描き起こし（`src/forms/nanbuSheets.ts`）
- 穿孔時の確認（実物の 10 項目）を図面と入力から ✓/⚠/□ で判定（`drillChecks`）。臨時給水ありで使用者が施主のままなら知らせる（誓約書の第 1 項）
- 製品一覧表（南部の様式）: 器具とヘッダーから行、メーカーと認証は画面で選び、種類ごとにこの端末に覚える。図に無い製品（食洗機など）は 1 行ずつ入力（`src/forms/fixtureProducts.ts`、`src/ui/ProductMakers.tsx`）
- 「📄 確認申請書から入れる」（全自治体）: 確認申請書・確認済証の PDF の文字を読み、空欄の項目だけに入れる。〔〕【】、様/殿、漢字の入った確認番号にも対応。スキャンの PDF は読めないと知らせる（`src/forms/kakunin.ts`、`src/import/pdfText.ts`）
- 自動の屋外の給湯を PB に。HT（材質が空欄の給湯を含む＝積算と同じ扱い）が残っていてガス給湯器がある工事は積算の要確認に
- プロファイル: 南風原町の給水図面を受理された実例の体裁に（A4 縦・受付欄・表題欄・アイソメ）、八重瀬町を追加。南部水道企業団の設計水圧 0.2MPa
- 画像の切り抜き（Sheet の image に clip。SVG は clipPath、PDF は re W n）。見取図を枠の形に切り抜いて大きく入れる（方位の N つき）

## 実物との照合（手元のみ）

- 様式の項目・並び・文言を実物と見比べた（作り物の値で描いた PNG）

## 独立監査（別エージェント・opus）
- Critical 1（実物由来の値がテストに混入）→ 作り物に置き換え、push 前に履歴を 1 つにまとめ直した
- Important 8 件を修正（各 RED→GREEN）: 【】括弧／殿・漢字の確認番号・確認済証の行より後ろだけ探す／空欄の給湯を屋内でも HT／誓約書の署名欄 3 つ（使用者の代表者を追加）／臨時給水と使用者の食い違いの知らせ／見取図を切り抜いて大きく／南風原町の下水道の体裁は未確認として残す／穿孔時の確認 1（チェックリストが全部済みで ✓）・5（使う水圧で判定、企業団 0.2MPa）
- 後回し（小）: pdf.js に cMap を渡していない（古い CJK の PDF）、候補が 0 のときの文言、チェック表の町名に印、誓約書の設置場所を町・字に分ける、工事が修繕でも臨時給水が既定で有り、ポンプを一覧に出す（計画は出さない）、図に無い製品のメーカーを行番号で覚える、メーカー入力ごとに端末へ保存、HT の要確認が区間ごと、外周をまたぐ所で給湯の区間を分け続ける、積算の説明文、選択肢を四角で囲む（楕円は描ける）
