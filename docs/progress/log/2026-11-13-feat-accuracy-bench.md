- 依頼: 「Pipecraft 3D 現行開発への統合指示」（追加費用なしで図面解析の精度を上げる。正解データとの数値比較を必須に）。ユーザー: 聞かずに全フェーズを進める
- P0 精度を測る仕組み `src/bench/`（使い方 `docs/bench/README.md`）
  - 正解 `truth.ts`（数値だけ・zod。`confirmedBy`/`confirmedAt` が無ければ「未確認」）。人が直して書き出した工事（`.pipecraft.json`）をそのまま正解にできる `fromDoc.ts`（画面を増やさない）
  - 比べ方 `evaluate.ts`: 図面の種類・縮尺の正誤／階高・GL〜床の誤差／壁の再現率・適合率（芯 100mm・向き 5°）と厚さの誤差／開口の数／器具・配置図の物（種類・階ごと 2,000mm 以内で組にし不足・余分・位置の誤差）／要確認の数。`reading.ts`（読み取り結果 → 比べる形）、`report.ts`（Markdown）
  - 基準 `synthetic.bench.test.ts`: 作り物の戸建・2 階建て共同住宅。今の値（図面 4/4、壁 99% 以上、器具・配置図すべて、位置の誤差 器具 100mm・配置図 10mm 以内）を下回ると `npm test` で落ちる
  - 手元の実物: `npm run bench -- bench-data`（`bench-data/` は .gitignore）。Node で pdf.js を使うため `importPlanSet` の PDF の読み込みを `readPlanInputs` に分けて共用
  - 実物 1 件（木造平屋・プロジェクトの 4 枚）で動作確認: 図面の種類 4/4・縮尺 4/4。壁・器具の正解は人の確認待ち（下書きのみ、リポジトリに入れていない）
- P1 確からしさ: 読み取りの「確かめてほしいこと」に level（low = 読めなかった・mid = 推定/標準値/目安・info = お知らせ）`ImportReport.levels`。画面は ❗ → ⚠ → ℹ の順、見出しに「要確認: 読めなかった n 件・推定・目安 n 件・器具の位置が大まか n 個」`confidence.ts`
- P2 数量の照合 `quantity.ts`・`design.ts`: 読み取り結果に器具の候補を全部置き、画面と同じ決まり（自治体の土かぶり・勾配、埋設深さ）で「まとめてつなぐ」→ 材料集計 と、実際の数量（truth.json の quantities）を品目ごとに。管は管種＋口径（φ の後ろ）、部品は名前＋口径。見出しは管の長さの誤差（差の合計 ÷ 実際）・部品の数の誤差・実際に無い品目の数
  - 気づき（実物 1 件）: 配置図に公共ますの記号が無い図面では、自動の排水が φ75・50・40 の床下の管だけで、屋外の VU φ100 が 0m（公共ますを置けば出る）。実際の数量と比べるときは公共ますを置いた状態にする必要あり → 次の課題
